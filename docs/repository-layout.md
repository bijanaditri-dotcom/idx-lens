# Where each part belongs

The repository stores the working backend and visual dashboard together. Keep
Python commands at the repository root and frontend commands inside `web/`.

| Path | Responsibility |
| --- | --- |
| `collector/` | Corrected Yahoo chart HTTP collector and placeholder configuration. |
| `api/` | FastAPI application and placeholder configuration. |
| `sql/` | MySQL bootstrap schema and starter tickers. |
| `scripts/` | Backend/API/Git checks and environment-version recording. |
| `tests/` | Isolated Python backend tests. |
| `web/` | React/TypeScript visual application and its existing server routes. |
| `web/components/dashboard/` | Dashboard, charts, dialogs, research overview, and stock detail. |
| `web/app/globals.css` | Main visual styling. |
| `web/lib/server/` | Existing frontend server-side providers and research storage logic. |
| `web/tests/` | Frontend/server TypeScript tests. |
| `docs/` | Shared project scope, roadmap, and integration documentation. |

## What the three ZIPs are

| Download | Contents | Relationship to this repository |
| --- | --- | --- |
| `idx-lens-mysql-integration(1).zip` | Original 15-file backend package, including the older yfinance collector and generated bytecode. | Historical starting point. The working repository already includes subsequent corrections. Do not extract the old package over the working project. |
| `idx-lens-stage1(1).zip` | 26-file setup kit: installer, Git settings, updated docs/dependencies, checks, and tests. | The applied support files are already committed at the repository root. The ZIP and installer are not needed in Git. |
| `idx-lens-visual-dashboard-source.zip` | 175 tracked source files from hosted dashboard version 12. | Imported into `web/`; the platform-specific hosting identity is omitted. Real environment values and hosted database contents were not part of the export. |

The source import leaves existing Python code, SQL, credentials, and the
virtual environment in place. It does not copy a nested `.git` repository,
installed Node packages, build output, or the hosted research database.

## Run the local visual dashboard on Windows

From the repository root in a new PowerShell terminal:

```powershell
Set-Location .\web
npx.cmd --yes pnpm@11.25.0 install --frozen-lockfile
```

For a fresh frontend configuration, copy the placeholder template only when
`.env.local` does not already exist:

```powershell
if (-not (Test-Path .\.env.local)) { Copy-Item .\.env.example .\.env.local }
npx.cmd --yes pnpm@11.25.0 run dev:next --hostname 127.0.0.1
```

Open `http://127.0.0.1:3000`. Leave this terminal running. The Python API can
continue in its own terminal on port 8000.

The default frontend uses labelled demo data. Its existing provider contract
does not match the FastAPI quote array directly; the MySQL adapter is still
planned. Do not embed the Python API bearer token in browser code.

## Git workflow

Run Git and the Python Git check from the repository root, not from `web/`:

```powershell
git status --short
git add README.md docs web
.\.venv\Scripts\python.exe .\scripts\check_git.py --staged
```

Review the staged files, then commit and push. The existing Backend checks
workflow scans the newly tracked files and runs the Python tests; it does not
build or test the frontend yet. Frontend checks can be run separately using
the commands in `web/README.md`.

Adding source to GitHub saves code. Public website deployment and connecting
the local database are separate steps. The imported server-based application
requires adaptation before it can be served as a static GitHub Pages site.
